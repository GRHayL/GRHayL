## Doxygen

`Doxyfile` declares the documentation input boundary:

- `INPUT = GRHayL docs/raw`
- `RECURSIVE = YES`
- `EXCLUDE = GRHayL/include/ghl_unit_tests.h`
- `EXCLUDE_PATTERNS = *.py`
- `USE_MDFILE_AS_MAINPAGE = docs/raw/mainpage.md`
- Root-level `DoxygenLayout.xml` is auto-parsed by Doxygen when present and
  can affect generated page layout (its header marks it as generated by
  doxygen 1.8.17, so it may be a stock rather than customized layout);
  review it with `Doxyfile` when docs structure changes.

Generated documentation output goes under `docs` because
`OUTPUT_DIRECTORY = docs`, with HTML enabled and LaTeX disabled. Treat
`docs/raw/` as source documentation and Doxygen HTML/output artifacts under
`docs` as generated output. Because the output directory contains the source
docs subtree, review Doxygen changes carefully before deleting or regenerating
anything under `docs`.

## Test Binaries And Downloaded Data

`configure` discovers `Unit_Tests/unit_test_*.c` and
`Unit_Tests/data_gen/unit_test_data_*.c`, then generated Makefile targets build
executables under `test/` and `test/data_gen/`.

`.github/run_tests.sh` downloads runtime fixtures into the repo root before
running tests. Downloaded file classes include:

- `*.bin` fixtures from repo-visible `GRHayL/TestData` raw paths;
- `simple_table.h5` from the same fixture source;
- `LS220_234r_136t_50y_analmu_20091212_SVNr26.h5.bz2`;
- `SLy4_3335_rho391_temp163_ye66.h5.bz2`.

The script decompresses downloaded `*.bz2` EOS tables and removes root-level
`*.bin`, `*.h5`, and `*.bz2` files at the end. If a test run stops early,
these downloaded root-level fixtures may remain as local artifacts.

`Unit_Tests/sample_table/generate_simple_table.py` creates `simple_table.h5`
from analytic arrays. The checked-in
`Unit_Tests/sample_table/Hempel_SFHoEOS_rho222_temp180_ye60_version_1.1_20120817_simple.h5`
is a sample table file, not a build artifact from `configure`.

## Flux Source Python And NRPy

Route Flux_Source-specific generator/script questions through
[Flux Source generated NRPy boundary](gems/flux-source/generated-nrpy-boundary.md).
This page keeps repository-wide generated-output boundaries; the child page
owns Flux_Source generator-script, NRPy support, and checked-in kernel routing.

`GRHayL/Flux_Source/*.py` and `GRHayL/Flux_Source/nrpy/` are source/generator
inputs for symbolic/NRPy-derived flux-source code. `Doxyfile` excludes `*.py`
from generated docs.

- `GRHayL/Flux_Source/GRHayL_rhs.py` imports NRPy support modules and calls
  `Cfunction__GRMHD_SourceTerms(".", includes)`.

  naming and imports. Exact upstream sync process: Unknown / needs maintainer
